    01 · El rol de Power BI en un engagement

    El instrumento de medición del proyecto.

    Power BI no es "una herramienta de visualización" en LCG. Es la capa que transforma el MEF de un modelo conceptual en una cifra que se mide cada semana. Cuando el Director de Operaciones abre la Junta Semanal de Avance, el primer slide es un dashboard de Power BI.

    Cada engagement LCG produce uno o más reportes publicados al workspace del cliente, conectados al modelo del MEF y refrescados con la frecuencia comprometida en el Componente 02 del MEF.

    02 · Setup técnico

    Lo que necesitas instalado el día 1.

    LCG tiene licencia Power BI Pro para todo el equipo de Operaciones, vinculada a tu cuenta M365. El stack de tu laptop debe quedar así:

    1. Power BI Desktop

      Aplicación local donde construyes el modelo y los reportes. Descarga desde Microsoft Store (versión auto-actualizable, recomendada). Solo Windows — en Mac se trabaja por Parallels o RDP a una VM corporativa.

    2. Power BI Service

      Acceso web en app.powerbi.com con tu cuenta @londoncg.mx. Aquí publicas los .pbix y se asignan permisos por workspace.

    3. Power BI Mobile

      App iOS/Android para revisar dashboards en cliente. Útil cuando estás en planta y no tienes laptop a la mano.

    4. On-premises Data Gateway

      Solo cuando el cliente tiene fuentes locales (SQL Server, ERP on-prem). Lo coordinas con el equipo de TI del cliente — TD/Sistemas LCG ayuda con la configuración inicial.

    5. DAX Studio & Tabular Editor

      Herramientas de productividad gratuitas. DAX Studio para auditar fórmulas pesadas; Tabular Editor para editar el modelo más rápido que en Desktop.

    03 · Modelo de datos LCG

    Esquema en estrella, siempre.

    LCG usa modelo en estrella con una tabla de hechos central (KPIs medidos por área, periodo y proyecto) y tablas de dimensión que describen el contexto. Esta forma asegura que el mismo modelo sirve para varios dashboards sin tener que reescribir DAX.

    Relaciones

    Todas las dimensiones se conectan al fact por su id con cardinalidad 1 → muchos y dirección de filtro simple. Nunca filtros bidireccionales — generan ambigüedades en DAX y son la causa #1 de mediciones "raras" en dashboards LCG.

    04 · DAX esencial para consultor LCG

    Las cinco fórmulas que cubren el 80%.

    No necesitas ser experto en DAX. Necesitas dominar cinco patrones que cubren la mayoría de cálculos en un dashboard de proyecto: cumplimiento, delta vs. Periodo Base, ratios ponderados, year-to-date y moving average.

    Patrón 01

    % Cumplimiento vs. meta

    El KPI base de cada indicador del MEF.

    % Cumplimiento =
DIVIDE(
  SUM(fact_kpi_proyecto[valor]),
  SUM(fact_kpi_proyecto[meta]),
  0
)
    Patrón 02

    Delta vs. Periodo Base

    El corazón del MEF — beneficio capturado.

    Delta vs. Base =
VAR base =
  CALCULATE(
    SUM(fact_kpi_proyecto[valor]),
    dim_periodo[es_periodo_base] = TRUE
  )
RETURN SUM(fact_kpi_proyecto[valor]) - base
    Patrón 03

    Cumplimiento ponderado

    Avance global del proyecto, ponderado por peso del indicador en el MEF.

    Cumpl. Ponderado =
SUMX(
  dim_indicador,
  [% Cumplimiento] * dim_indicador[peso_mef]
)
    Patrón 04

    YTD acumulado

    Para el reporte mensual al cliente.

    Valor YTD =
TOTALYTD(
  SUM(fact_kpi_proyecto[valor]),
  dim_periodo[fecha]
)

    Moving average de 4 semanas

    Útil para suavizar ruido semanal en indicadores volátiles (ventas, pedidos atendidos, OEE). 

    // MA 4 semanas — suaviza ruido y resalta tendencia
MA 4S =
VAR ult_fecha = MAX(dim_periodo[fecha])
VAR rango = DATESINPERIOD(dim_periodo[fecha], ult_fecha, -28, DAY)
RETURN
  CALCULATE(
    AVERAGEX(VALUES(dim_periodo[semana_iso]), [% Cumplimiento]),
    rango
  )
    05 · Plantilla LCG · diseño

    Una sola plantilla, en todos los proyectos.

    LCG mantiene una plantilla maestra LCG_Dashboard_v3.pbix en el SharePoint de Sistemas y Digital MX. Toda nueva construcción parte de ahí — colores brand aplicados, theme JSON cargado, layouts predefinidos.

    Estructura estándar (4 páginas)

    1. 01 · Resumen ejecutivo

      KPIs maestros + cumplimiento ponderado + delta vs. base. Lo que el Director Ops ve en la JSA.

    2. 02 · Detalle por área

      Una página por área del MEF. Indicadores individuales, tendencias, top issues.

    3. 03 · Iniciativas

      Estatus de cada iniciativa (en curso, riesgo, completada) con responsable y fecha compromiso.

    4. 04 · Datos & metodología

      Glosario de indicadores, fuentes, fórmulas. Audit trail para Finanzas del cliente.

    El theme JSON LCG es no negociable.

    Carga lcg-theme-v3.json al primer abrir un .pbix nuevo. Te aplica paleta brand (verdes LCG + neutros), tipografía Manrope/Fraunces fallback y estilos consistentes para tarjetas, gráficos y textos. Sin theme cargado, el dashboard no se publica al workspace cliente.

    06 · Publicación & permisos

    Workspace por cliente, RLS por rol.

    Cada engagement tiene su propio workspace en Power BI Service: LCG · {cliente}. Permisos limitados a equipo del proyecto + Director del área cliente + Top Client. Publicar fuera de un workspace formal está prohibido por política de seguridad.

    Row-Level Security (RLS)

    Cuando el dashboard se comparte con varias personas del cliente y cada una solo debe ver su área, se configura RLS en el modelo. Patrón estándar: 

    // Rol "Director de Área" — ve solo su área
[Filtro] = dim_area[director_area] = USERPRINCIPALNAME()

    Frecuencia de refresh

    Diario a las 06:00 hora CDMX es la cadencia estándar para que la JSA del lunes encuentre datos frescos. Cuando el cliente requiere monitoreo cercano (Excelencia Comercial con dashboards de venta diaria), se pasa a cada 4 horas.

    07 · Buenas prácticas

    Lo que separa un PBIX limpio de uno quemado.

    Hacer

    • Nombrar tablas con prefijo: fact_, dim_.
    • Crear medidas en una tabla "Medidas" sin columnas, no en tablas de hechos.
    • Usar DIVIDE() en vez del operador / — maneja división por cero.
    • Cargar el theme LCG antes de poner el primer visual.
    • Documentar fórmulas complejas con comentario inline (// ...).
    • Versionar el .pbix en SharePoint con sufijo _v01, _v02.

    Evitar

    • Cargar tablas con miles de columnas que no usas — pesa y ralentiza refresh.
    • Filtros bidireccionales entre dimensión y fact (ambigüedades DAX).
    • Calcular en el visual con "Quick Measures" sin saber qué fórmula generaron.
    • Publicar el .pbix con queries apuntando a tu carpeta local C:\Users\....
    • Subir el .pbix con datos del cliente al repo de Sistemas (sin anonimizar).
    • Compartir reportes por link público — siempre por workspace.
    08 · Cierre

    Antes de pasar al siguiente bloque

    Cuando entres a tu primer proyecto, abre el workspace del cliente en Power BI Service y revisa el .pbix activo. Identifica las tablas de hechos, las dimensiones y dónde está el cálculo del MEF. Esa lectura te ahorra dos semanas de preguntar.
